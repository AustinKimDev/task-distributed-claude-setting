# /go — 즉시 실행: 파이프라인 자동 적용

작업 지시를 받으면 아래 규칙을 자동 적용하고 즉시 실행을 시작한다.
매번 반복 지시할 필요 없이 이 스킬 하나로 모든 실행 규칙을 활성화한다.

---

## 1. 병렬화 규칙

**기본값: 병렬.** 순차는 의존성이 있을 때만.

- 독립 태스크 → 별도 에이전트로 동시 디스패치
- 파일 충돌 가능성 → 워크트리 격리
- 하나의 메시지에 여러 Agent 호출을 묶어 동시 실행
- 3개 이상 병렬 에이전트 시 Phase 분리 (Phase 1: 독립, Phase 2: 조립)

## 2. 모델 라우팅

| 역할 | 모델 | 사용 시점 |
|------|------|----------|
| 오케스트레이션 | opus (현재 세션) | 분류, 계획, 디스패치, 종합 |
| 구현 서브에이전트 | sonnet | 코드 작성, 리팩터, 테스트 |
| 탐색/검색 | haiku | 파일 찾기, 코드 검색, 빠른 확인 |
| 복잡한 추론 | opus | 아키텍처 결정, 디버깅 난제 |

**반드시 `model` 파라미터를 명시한다.** 생략 금지.

## 3. 워크트리 정책

| 분류 | 워크트리 |
|------|----------|
| Fast | 브랜치만 (단일 에이전트) |
| Standard | 워크트리 필수 |
| Critical | 워크트리 필수 |

- 에이전트에 `isolation: "worktree"` 설정
- 또는 에이전트 프롬프트에서 직접 워크트리 생성 지시
- 워크트리 내에서만 코드 수정. main 직접 수정 금지.

## 4. 파이프라인 (Inner Work Loop)

각 서브에이전트는 이 루프를 따른다:

```
STEP 1: Discovery — 파일 읽기, 스코프 확인
STEP 2: Planning — 접근법 확정 (복잡한 태스크만)
STEP 3: Implementation — 코드 작성, 1 변경 = 1 커밋
STEP 4: Build & Test — 빌드/린트/테스트 실행
STEP 5: Review — 셀프 리뷰 (Fast: skip, Standard: light)
```

## 5. 에이전트 프롬프트 템플릿

서브에이전트 디스패치 시 이 구조를 따른다:

```
You are implementing [TASK NAME] for the [PROJECT] project.

## Context
- [프로젝트 스택, 디자인 원칙 등 필수 컨텍스트]
- [관련 파일 경로]

## Task
[구체적인 작업 내용 — 파일, 라인, 변경 사항 명시]

## Constraints
- [기존 API 계약 유지 등]
- [사용할 컴포넌트/라이브러리]

## Definition of Done
- [완료 기준 — 빌드 통과, 특정 동작 확인 등]

Commit each logical change. Korean UI text.
```

## 6. 즉시 실행 절차

이 스킬이 호출되면:

1. **분류 선언** — `이 작업을 [Fast/Standard/Critical]으로 분류했습니다.`
2. **태스크 분해** — 멀티 태스크면 분리 + 의존성 맵
3. **에이전트 디스패치** — Phase 1 병렬 즉시 실행
4. **대기하지 않음** — Phase 1 실행 중 독립적으로 할 수 있는 작업 진행
5. **Phase 2** — Phase 1 완료 후 조립/통합 태스크 실행
6. **머지 리포트** — 전체 완료 후 요약 보고

**승인 대기 규칙:**
- Fast → 즉시 실행, 보고만
- Standard → 계획 제시 후 1회 승인 대기
- Critical → 계획 제시 후 2회 승인 대기 (계획 + 실행 전)
